---
name: video-thumbnails
description: Explore YouTube thumbnail options for one video in Canva. Opens a Canva file for the video, builds variants from Matt's existing thumbnails and real photos, and shows them on an inline board he picks from, round after round. Use when Matt is making, editing, or choosing thumbnails for a video, or asks for thumbnail options, variants, or versions.
---

Each video gets its own Canva design, so experiments never touch the shared `Thumbnails` design (`DAHGIaJOQoI`). Every round shows variants on one board built from [`board.html`](board.html). The comment at its top is the template contract. Matt answers with a letter and what to change, and the next round branches from his pick.

1. **Brief.** Get the video's working title, the idea the thumbnail sells, and a starting point: pages of `Thumbnails` he likes (`read-design` with `thumbnails` to show candidates), a face expression, or text to try. Ask only for what is missing. Done when you can name the baseline layout and the first variables to test.
2. **Open the video's file.** Use one `merge-designs` call with `type: "create_new_design"` and title `Thumbnail – <video title>`. Give it one `insert_pages` operation per variant, each copying the baseline page from `Thumbnails`, so every variant starts as an identical copy. Canva requires approval of the exact operations before every `merge-designs` call, so state them in one line and wait for OK. Done when the design exists and you have its `design_id` and `edit_url` (from `read-design`).
3. **Build variants.** Page 1 is the baseline. Every other page is the baseline with one thing changed (face, hook text, layout, background, colour, crop). Usually 4 to 6. Change each page in one `edit-design` transaction (`read-design` with `open_transaction: true` gives the element locators). Faces are real photos only: use the Matt Faces folder (`FAHFpUBQb2U`) and `remove-background`. Never use image generation on his face. For tweet-style variants, follow the `tweet-thumbnail` skill. Done when each page shows a different single change.
4. **Show the board.** Download each page's preview to `canva-previews/<video-slug>/r<round>-<letter>.png`. Use `read-design` thumbnails (inside the open transaction for unsaved edits) or `export-design` PNG at 1280 wide. Copy `board.html` to `canva-previews/<video-slug>/board.html` and fill in `BOARD` with absolute paths. In T3 Code, check it with `html_preview`, then publish it with `html_render` above the reply. Elsewhere, open the file and embed the PNGs inline. Done when every variant appears on the board with its letter and one-line note.
5. **Save on approval.** The draft only becomes permanent when Matt reacts to the board. Commit the transaction once he picks or says keep. If he rejects the round, cancel it. Done when the picked page is saved and nothing he rejected was committed.
6. **Iterate.** Each follow-up is a new round. The pick becomes the baseline, and new variants each change one more thing in the direction he asked. Add copies of the pick to the same design with `merge-designs` (`type: "modify_existing_design"`, `insert_pages` from its own `design_id`), then build the next round number and a fresh board. Earlier boards stay in the thread for comparison. Done when he calls one final.
7. **Finish.** Export the final page as PNG at 1280 wide to `canva-previews/<video-slug>/final.png`, show it inline, and give the Canva `edit_url`. In T3 Code, that link opens in the Browser panel when Settings → Integrations → "Open links in" is set to T3 Code, so he can drag things by hand next to the chat.

Canva doesn't allow its editor to be embedded in other apps, so the board is a preview with a link out, not the live editor. Clicking a variant only enlarges it. Matt picks by replying with its letter.
